# P3 · 判定 / 补全检查 / 补全卡

> 输入：`mode` 与对应字段。输出：一个 JSON 对象。**只判这一道题的回答，不汇总报告。**

## mode = `judge`

输入：

```json
{
  "mode": "judge",
  "question": { "id": "Q1", "type": "复述解释题", "quote": "……", "rubric": { "expected_points": [], "must_not": [] } },
  "answer": "用户原话（可能只有一句，也可能是“不确定”）",
  "dial": 3,
  "followup_used": false,
  "second_pass": false
}
```

### 判定顺序（必须按这个顺序，不许凭整体印象）

1. **先判命中**：逐条对照 `expected_points`，标出命中与缺失；命中必须有用户原话作依据。
2. **再判冲突**：是否出现 `must_not` 中的说法，或与 `quote` 冲突、答非所问、编造报告里没有的内容。
3. **最后给 verdict**：
   - `correct`：按严格度命中足够要点，且无冲突；
   - `partial`：命中部分要点，或只有结论没有理由，或只是换词复述；
   - `wrong`：与原文冲突、答非所问、编造报告外内容；
   - `unsure`：用户明确回答“不确定”（同义说法也算），单列，**不算错**。
4. **追问最多 1 次**：`followup_used: false` 且 verdict 为 `partial` 时，可给 `followup` 建议；`followup_used: true` 仍为 `partial` → 维持 `partial`，不再追问。

### 严格度（由 `dial` 决定，不得自行加严）

| dial | 判 `correct` 的条件 |
|---|---|
| 1–2 | 命中前两条核心要点，且无明显冲突 |
| 3 | 命中全部 `expected_points`，且无冲突 |
| 4 | 全部要点 + 说清结论成立的条件，否则最高 `partial` |
| 5 | 全部要点 + 条件 + 举一个报告里的例子，否则最高 `partial` |

### 可靠性

- `confidence` ∈ [0,1]：要点是否明确、回答是否含歧义；`confidence < 0.7` 时由调用方二次判定。
- 两次判定不一致 → `needs_review: true`，**不直接记错**，界面提示“这题判得不确定，建议你自己再看一眼”。
- `evidence` 必须引用用户原话（截断到 80 字内）；没有原话依据就降低置信度。
- `reread` 给 1–2 条回读位置，指向报告的具体段落或原句，不写“再读一遍全文”。
- `second_pass: true` 时是低置信度的独立复核：重新逐条对照要点，不沿用上一次结论；输出同样字段。

输出：

```json
{
  "mode": "judge",
  "question_id": "Q1",
  "verdict": "partial",
  "hit_points": ["追问发生在学习过程中"],
  "miss_points": ["未说明追问为什么能提升参与度"],
  "conflict": false,
  "evidence": "用户原话：“就是多问几句，让学生多想。”",
  "confidence": 0.82,
  "needs_review": false,
  "reread": ["§2 第 2 段：追问的三个时机"],
  "disclaimer": "这是对这道题回答的判定，不是对报告的评分。"
}
```

## mode = `refill_check`

输入：`node_id`、`quote`、`refill_text`（用户写的一句补全）。
只查两件事：**是不是自己的话**、**有没有指向这个概念**。**不判对错**。

- 空着、整句照抄原文、跑题 → 对应字段 `false`，`note` 提示重写，不算失败。
- 输出：

```json
{
  "mode": "refill_check",
  "node_id": "T3",
  "is_own_words": true,
  "on_topic": true,
  "note": "用自己的话说明了“思考投入”，但没有提“不是行为次数”。"
}
```

## mode = `micro_explain`

输入：`node_id`、`quote`、`source_span`（可选）、`report_text`。
生成一张 80–120 字的补全卡正文，**只能重组 `quote` 里已经有的信息**：

- 不引入报告外的事实、数据、文献、定义；
- 不写成小课堂，不给“标准答案”，最多把原文的因果链说得更直白；
- 报告没讲清时，`micro` 写“报告没有展开这一点。”并给回读位置，`grounded: false`。

输出：

```json
{
  "mode": "micro_explain",
  "node_id": "T3",
  "source_quote": "该方案通过过程性追问提升学生的认知参与度。",
  "source_span": "§2 第 1 句",
  "micro": "报告里的“认知参与度”指思考投入的深浅，不是举手或发言次数。",
  "grounded": true
}
```

## 禁止

- 出现分数、百分比、等级、星级、排名；
- 把 `wrong` 写成“不合格 / 抄袭 / 学术不端”；
- 由一道题的判定推断整篇报告的质量；
- 在补全卡里编造报告没有的内容；
- 输出 JSON 以外的任何文字。
