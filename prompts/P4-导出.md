# P4 · 题库导出（JSON + Markdown）

> 输入：一次审计的完整记录（graph、questions、judgments、skipped/refilled/reasked、dial、recording）。
> 输出：一个 JSON 对象，含 `quiz`（题库 JSON）与 `markdown`（给用户看的复盘）。**只整理，不再出题、不再判定。**

## 导出前处理

1. **脱敏**：删除姓名、学号、手机号、邮箱、导师姓名、未公开项目名；用 `〔已脱敏〕` 占位。`report_span` 只保留到 80 字。
2. **隐藏来源**：`origin` / `origin_basis` 默认不导出；学生版任何位置都不出现 `human` / `ai` / “AI 占比”。
3. **不导出对话原文**：只保留每题 `用户回答` 的必要截断（≤200 字）与判定依据中的 `evidence`。
4. **不汇总分数**：可以写“对 N 题 / 部分对 N 题 / 错 N 题 / 跳过 N 题 / 不确定 N 题”，但不给正确率、百分比、等级、排名。
5. **记录不完整要写**：`recording.complete = false` 时，在 Markdown 开头标“记录不完整”，列出 `gaps`；未覆盖片段按 `unknown`，不假装已验证。
6. **来源仍隐藏**：`origin` / `provenance` 不进入学生版导出。

## `quiz` 字段

与 `templates/题库字段.schema.json` 一致。必填：`id`、`阶段`、`题型`、`档位`、`来源原文`、`题目`、`期望要点`、`用户回答`、`判定`、`判定依据`、`时间戳`。可选：`entry_id`、`component_id`、`variant_of`、`dial`、`spot_check`。

- `阶段`：`first_pass` / `reask` / `spot`；
- `判定`：`correct` / `partial` / `wrong` / `unsure` / `skipped`；
- `判定依据`：`hit_points`、`miss_points`、`evidence`、`confidence`、`needs_review`、`first_verdict`；
- 跳过题：`判定: "skipped"`，`判定依据.evidence` 写“用户主动跳过”，不得写“未掌握/失败”。

## `markdown` 固定结构

```markdown
# 理解审计 · 复盘

> 本结果是对你理解状态的一次抽样提示，不是评分，也不代表报告内容正确或错误。题目只覆盖了本轮抽到的知识点，未覆盖的部分不代表没有问题。请把它当作回读的线索，而不是结论。

- handoff：h-YYYYMMDD-001
- 深度：3（4 题 · 抽查 30%）
- 本轮：4 题（正常档 2 · 简单档 1 · 抽查 1）；升级 1 处；回访 0 题

## 缺口地图

| 状态 | 节点 | 知识点 | 说明 |
|---|---|---|---|
| ● | R2 | 工具能识别虚假掌握 | 判定：对 |
| ◐ | R1 | 过程性追问→认知参与度 | 简单档部分对，升级后仍有缺口 |
| ○ | T3 | 认知参与度 | 判定：错（术语讲错） |
| ⊘ | T5 | 虚假掌握 | 主动跳过，未补全 |
| ◌ | T3 | 认知参与度 | 已补全，等待再问 |
| · | T2 | 最近发展区 | 预算用完，本轮未考察 |

符号：`●` 已通过 / `○` 有缺口 / `◐` 升级过 / `⊘` 跳过待补 / `◌` 补全待回访 / `·` 未考察。

## 逐题

### Q1 · 复述解释题 · 正常档
- 来源原文：“……”
- 题目：……
- 你的回答：“……”
- 判定：部分对（partial）
- 命中：……
- 缺失：……
- 追问：已用 1 次
- 回读：§2 第 2 段

## 回读建议
1. §2 第 2 段：三种追问时机的区别，重点看“为什么在过程中问”。
2. §3 末段：“认知参与度”的操作定义，对照你回答里用的说法。
```

## 自检

- [ ] 没有姓名/学号/导师/项目号；没有 `origin`
- [ ] 没有正确率、百分比、等级、星级、排名
- [ ] 跳过题写“主动跳过”，未考察写“本轮未考察”
- [ ] `markdown` 与 `quiz` 的题目、判定一一对应
